# Operator Manual — Печать PDF в школьную тетрадь через UMTS на Bambu Lab P1S

Полное руководство «от ноля до напечатанной тетради».

Связанные документы:
- [`umts-p1s-pen.md`](umts-p1s-pen.md) — инструкция UMTS (механика, безопасность, калибровка)
- [`pipeline.md`](pipeline.md) — техническое описание скриптов и тулчейна
- [`runlog.md`](runlog.md) — журнал прогонов и калибровок

---

## Веб-клиент (самый простой способ)

```bash
./scripts/webui.sh                  # http://127.0.0.1:8765, откроется браузер
./scripts/webui.sh --demo-printer   # без принтера: встроенный фейковый P1S, ускоренное время
```

- **Сборка** — выбрать или загрузить PDF, держатель, порядок страниц, подъём/скорость/ускорение пера → «Собрать тетрадь». Живой лог внизу; после сборки — итог проверки на модели и превью всех страниц (серое — исходные буквы, чёрное — перо, красное — чернила вне букв, синее — буква без чернил).
- **Файлы** — все задания с оценкой времени и статусом проверки на модели (PASS/FAIL/устарела), отчёт, превью, скачать, «На принтер».
- **Предпросмотр движения** (или кнопка «Движение» в таблице файлов) — одна страница задания на столе P1S в масштабе: текстурная плита, лист в клетку, L-упор, держатель (радиус 12 мм) и сопло, шкала Z. Таймлайн идёт по модели планировщика: «Пуск» ×1…×1000, перемотка ползунком или кликом по полосе под ним (синее — пишет, жёлтое — подъём/опускание, красное — переезд; оранжевые метки — паузы, красные — ошибки из отчёта модели). Колесо — зум, перетаскивание — сдвиг, «следить за пером» — камера за пером. Справа — время страницы, число подъёмов, доля времени на письмо/подъёмы/переезды и текст паузы этой страницы.
- **Калибровка** — листы zbench / лесенка / скорости / проверка упора / страница на замер и STL L-упора с теми же параметрами пера; «Скачать L-упор (STL)» отдаёт `output/l_stop.stl`.
- **Принтер** — IP, серийный номер, access code (хранится в `~/.config/pdf-to-print/printer.json`, права 600, в браузер не отдаётся) → «Подключиться». Состояние, прогресс, страница k из N, пауза / продолжить / стоп, снимок камеры, отправка задания по LAN.

Значок «?» рядом с параметром объясняет, что он делает и когда его менять.

На каждой паузе сверху появляется жёлтая полоса с действием: «Установите держатель…», «Положите страницу 23: разворот 1, правая, внутренняя», «Снимите держатель и нажмите Стоп», со звуком и системным уведомлением (кнопка «Включить уведомления»).

**Отправка по LAN.** Файл упаковывается в `.3mf` (`Metadata/plate_1.gcode`), загружается по FTPS на SD-карту и запускается командой `project_file`. Отправка разрешена только для файла с PASS на модели для выбранного держателя (флажок «без проверки» — на свой риск). Перед стартом держатель снят: первая пауза — установка.

⚠️ С прошивки 01.08.02 принтер принимает **команды** (старт, пауза, продолжить, стоп) от сторонних программ только при включённых **LAN Only + Developer Mode** на экране принтера. Статус и загрузка файла работают и без них. Клиент показывает, включён ли Developer Mode; если нет — используйте способ «Только загрузить» и запускайте файл с экрана принтера. Orca на время печати лучше закрыть: принтер держит около двух подключений.

Сборка не перезаписывает существующий файл без подтверждения (например, уже напечатанное задание).

## 0. Что это и какие требования

**Цель**: автоматически нарисовать содержимое 24-страничного PDF (текст в handwriting-шрифте) на школьной тетради 12 листов, формат страницы 165×205 мм, в landscape ориентации (тетрадь кладётся на стол набок).

**Железо**:
- Bambu Lab P1S
- UMTS pen-модуль (см. UMTS docs §"Положение бумаги", §"Z-Offset")
- Гелевая ручка Xiaomi MI Jumbo Gel Ink (или совместимая)
- Магнитный лист на стол + 4 неодимовых магнита для фиксации тетради
- Опциональный направляющий шаблон 24×50 мм (для повторяемого позиционирования бумаги от bed origin)

### 1.3.0 ⚠️ Положение тетради — bed-relative

**Тетрадь landscape (длинный край 205мм по X)**:
- 24 мм от **левого края bed plate** (X bed origin) до левого края тетради
- 50 мм от **переднего края bed plate** (Y bed origin, ближайший к двери) до переднего края тетради
- Замер с любой стороны рулеткой от металлического края плиты

**Pen offset**: ручка смещена от сопла на (-26.46, -37.9) мм. Pipeline это компенсирует — gcode командует сопло на (50.46, 87.9..255.46, 252.9), pen физически попадает в paper bounds (24..229, 50..215).

**Не путать с UMTS author's "29мм от right wall, 41мм от rear wall"** — у нас bed-relative, замер удобнее.

**Софт** (macOS):
- Inkscape ≥ 1.4
- Python 3.11–3.13 (3.14 не работает с vpype из-за `pkg_resources`)
- Orca Slicer (для G-code preview и LAN-печати)
- vpype + vpype-gcode (устанавливаются скриптом)
- Phase 1 по умолчанию: растр → скелет (`png_to_skeleton_svg.py`, нужны в `.venv`: numpy, scikit-image, networkx, Pillow — обычно уже стоят). Для legacy potrace: `brew install potrace imagemagick` и `TRACE_MODE=potrace`. Векторный Inkscape: `./scripts/build.sh … vector` или `USE_VECTOR_EXTRACT=1`.

### 1.2. P1S в LAN ONLY режим

Подробно — см. [`umts-p1s-pen.md`](umts-p1s-pen.md) §Слайсер и наш ранее обсуждавшийся гайд:

- Экран P1S → Settings → General → включить **LAN Mode Liveview**
- Записать Access Code (8 цифр) и IP принтера
- В Orca Slicer добавить принтер: Device → +, ввести IP, Access Code, Serial Number, выбрать «LAN Mode Only»

### 1.3. Настройки Orca — что РЕАЛЬНО нужно

Наш workflow: `output/notebook.gcode` отправляется через **Device → Open G-code File** байт-в-байт. Orca **не модифицирует** файл, profile-настройки **не применяются** к raw gcode.

Поэтому большинство настроек (filament temp, retraction, Z-hop, layer height, скорости, line width, XY компенсации) **не нужны** — они уже зашиты в нашем gcode либо неприменимы.

**Минимально достаточная настройка**:

#### A) Подключение принтера (обязательно)

Orca → **Device** tab → **+** → ввести:
- IP принтера (с экрана P1S → Settings → WLAN)
- Access Code (8 цифр, экран P1S → Settings → General)
- Serial Number (экран P1S → Settings → Device)
- Connection Mode: **LAN Mode Only**

Без этого не отправить gcode.

#### B) Z-offset — НЕ настраивается в Orca

Z-offset запекается в **наш gcode** через константу `Z_PEN_DOWN` в `scripts/svg_to_gcode.py` (по умолчанию 18.7 мм — старт для Stabilo и тонкой тетради; см. комментарий в файле). Калибровка Test 3 (см. §2) даёт финальное значение → правишь константу → перегенерируешь:

```bash
# В scripts/svg_to_gcode.py поменять:
#   Z_PEN_DOWN = 18.7  →  Z_PEN_DOWN = <откалиброванное>
./scripts/build.sh
```

**Z-offset из Orca printer profile НЕ применяется** к raw gcode — это slicer-time параметр. Можно оставить дефолт 0.

#### C) Excluded area, Start/End G-code в profile — необязательно

Эти поля Orca применяет только при **Slice**. Для нашего pipeline (Open G-code File без slice) они игнорируются.

**Если хочешь** заполнить (на будущее, для других проектов с UMTS):
- Printer Settings (✎ рядом со списком принтеров) → вкладка **Machine G-code** → **Machine start/end G-code**: вставить содержимое `templates/bambu_start.gcode` и `bambu_end.gcode`
- Printer Settings → **Basic information** → printable area → custom shape → excluded area: `( 0x0, 258x0, 258x55, 48x55, 48x258, 0x258 )`

Иначе — пропустить.

#### D) Filament/Process — пропустить

Полностью не нужно. Все эти параметры выражены литералами внутри `output/notebook.gcode`:
- `M104 S180` / `M109 S180` — nozzle temp (в start G-code)
- `M106 S0` × 3 — все вентиляторы выключены
- `G1 Z<Z_PEN_DOWN>` / `G1 Z<Z_PEN_DOWN+Z_HOP>` — pen-down / Z-hop (актуальные мм в `scripts/svg_to_gcode.py` и в сгенерированном gcode)
- `F6000` / `F30000` и `M204 S5000` — draw / travel / ускорение пера (env, см. §2.5)
- Layer height, line width, XY compensation, retraction, perimeters — всё уже было применено vpype-ом при генерации траекторий

Если в будущем захочется слайсить что-то руками с UMTS — настроишь process тогда.

### 1.3.1. ⚠️ Куда что вставлять — карта файлов

| Файл | Куда | Зачем |
|---|---|---|
| **`output/notebook.gcode`** | Orca → **Device** → **Open G-code File** → Print | Финальный артефакт. Self-contained (start + 24 страницы + паузы + end). Никуда больше не копируется. |
| `templates/bambu_start.gcode` | **Опционально**: Orca Printer Settings → Machine G-code → Machine start G-code | Применяется только при ручном Slice в Orca, для нашего pipeline не нужно |
| `templates/bambu_end.gcode` | **Опционально**: туда же → Machine end G-code | То же |
| `templates/vpype_profile.toml` | **Никуда не копировать вручную**. `~/.vpype.toml` авто-генерируется `svg_to_gcode.py` с подставленными Z-значениями | Файл-референс для понимания структуры профиля vpype |

### 1.3.2. ⚠️ Workflow печати — НЕ слайсить наш .gcode

`output/notebook.gcode` — **уже G-code**, не проект. В Orca отправляется через:

```
Orca → Device tab (вкладка с принтером) → Open G-code File → выбрать output/notebook.gcode → Print
```

**НЕ через**:
- ❌ File → Open → ... → Slice (Orca попытается распарсить .gcode как проект, упадёт или испортит файл)
- ❌ Drag-and-drop в окно Plate (та же ошибка)

Когда отправляешь GCODE FILE напрямую — Orca **НЕ применяет** свои Machine start/end G-code из profile, шлёт файл байт-в-байт. Поэтому дубль исключён: start уже в `output/notebook.gcode`, в Orca printer profile — на будущее (если будешь слайсить что-то ещё с UMTS-настройками).

Проверить self-contained-ность:
```bash
head -3 output/notebook.gcode    # ожидаем ";===== UMTS Pen Plotter Start..."
tail -3 output/notebook.gcode    # ожидаем "M84 ; motors off"
grep -c 'M400 U1' output/notebook.gcode    # 25 = 1 install + 23 page-flip + 1 end
```

## 2. Калибровка ручки и зоны (Test 1–4)

**Перед каждым тестом** — записать в [`runlog.md`](runlog.md) что собираемся проверить.

### Test 1 — пустая голова, проверка excluded zone

Цель: убедиться что G-code не выходит за пределы безопасной зоны UMTS, ничего не врезается.

```bash
./scripts/build.sh
```

Загрузить `output/notebook.gcode` в Orca → Device → Open G-code File → Print.

- БЕЗ модуля, БЕЗ ручки, БЕЗ бумаги
- Принтер пройдёт start G-code (wipe, leveling)
- На первой паузе («install module») — **не ставить модуль**, просто Resume
- Принтер начнёт «рисовать» ничем — только travel-движения
- Наблюдать визуально: голова не врезается в стенки, не цепляется за дверцу/стекло
- На любой паузе можно остановить (LCD → Stop)

→ Записать в runlog: «Test 1 OK / коллизии».

### Test 2 — модуль без ручки

То же, но с установленным UMTS-модулем без ручки.

- Цель: проверить что модуль с пружиной свободен в движении, не задевает стекло
- Z-offset должен быть +18 мм (или калиброванный)
- Прерываем после 1-2 страниц

### Test 3 — Z-калибровка с ручкой (детально)

Цель: подобрать правильное давление ручки на бумагу. Делается **физической регулировкой** глубины ручки в модуле UMTS, не правкой G-code (быстрее итерация).

#### Что делаем по сути

Модуль UMTS — это пружинный держатель. Ручка вставляется в него и выступает на какую-то длину ниже корпуса модуля. При G-code команде `G1 Z18` сопло встаёт на 18 мм над столом, и ручка касается стола (если выступает ровно на 18 мм). Если выступает БОЛЬШЕ — пружина сжимается → давление на бумагу. Если МЕНЬШЕ — ручка не достаёт → нет следа.

`Z_PEN_DOWN=18` в `scripts/svg_to_gcode.py` фиксирована. Регулируем **физически глубину ручки в модуле**.

#### Материалы

- Жертвенный лист A4 на столе (тот же магнитный фиксатор, что будет с тетрадью)
- UMTS модуль
- Xiaomi MI Jumbo Gel ручка
- Тестовый G-code: `output/calibration.gcode` (рисует 5 коротких линий, ~30 сек прогон)

#### Подготовка

```bash
python3 scripts/calibration_gcode.py    # сгенерирует output/calibration.gcode (1.7 КБ)
cp output/calibration.gcode /Volumes/<sd>/    # на SD
```

#### Цикл итерации (типично 3–6 итераций)

1. **Положить лист A4** на стол с тем же фиксатором, что планируется для тетради
2. **Запустить** `calibration.gcode` на P1S (с SD)
3. На первой паузе — **установить модуль с ручкой**:
   - В **первый раз**: вставить ручку с **запасом по высоте** — то есть выступает МЕНЬШЕ чем нужно (ручка задвинута глубоко в модуль). Так точно не упрёшься в стол на старте.
   - В последующие итерации — позиция ручки сохраняется или регулируется по результату прошлой итерации
4. **Resume** на LCD → принтер рисует 5 линий (~30 сек)
5. **На финальной паузе** — снять модуль, посмотреть на лист
6. **Оценить результат**:

| Что видишь | Диагноз | Действие перед следующей итерацией |
|---|---|---|
| Линий нет / еле видно | Ручка не достаёт до бумаги | Вынуть модуль, **подвинуть ручку вниз 1–2 мм** (выдвинуть ниже из корпуса), вставить обратно |
| Линии бледные, прерывистые | Контакт слабый, мажет | Подвинуть ручку вниз 0.5–1 мм |
| Линии чистые, ровные, насыщенные | ✅ Готово, **зафиксировать** ручку в этом положении (винт модуля если есть) | — |
| Линии есть, но ручка тащит чернила между линиями | Z-hop не работает или мал | Проверить что между штрихами подъём выше чем `G1 Z18` (напр. `G1 Z33` при Z_HOP=15). Если ОК — увеличить `Z_HOP` в `scripts/svg_to_gcode.py` |
| Ручка втыкается с щелчком, бумага продавлена | Слишком сильное давление | Вынуть модуль, **подвинуть ручку вверх 1–2 мм** (задвинуть глубже в корпус) |

7. **Stop** на LCD после финальной паузы (НЕ Resume — чтобы не запустить лишнее)
8. Снять лист, повторить с новым листом если нужна следующая итерация
9. **Записать в `docs/runlog.md`**:
   - Сколько итераций ушло
   - Финальная позиция ручки (можно отметить маркером на корпусе ручки длину выступа)
   - Качество линий

#### Альтернатива: правка `Z_PEN_DOWN` без снятия модуля

Если не хочется перевставлять ручку каждую итерацию, можно менять `Z_PEN_DOWN` в скрипте:

```bash
# Бледно → уменьшить Z_PEN_DOWN (ручка глубже в стол)
# Сильно давит → увеличить Z_PEN_DOWN (ручка выше)
# В scripts/svg_to_gcode.py:
#   Z_PEN_DOWN = 18.7  →  17.5  (бледно) или 19.0  (давит)
python3 scripts/calibration_gcode.py --z-down 17.5
cp output/calibration.gcode /Volumes/<sd>/
```

Минус: пере-генерация per-page gcode при финале (после калибровки нужно запустить полный `./scripts/build.sh` чтобы перегенерить notebook.gcode с новым Z_PEN_DOWN). Плюс: быстрая итерация без снятия модуля.

**Выбор подхода**: для гелевой ручки (мягкое давление) рекомендуется **физическая регулировка** — однажды настроил и забыл. Менять Z в скрипте — для жёстких ручек (POSCA), где допуск меньше.

#### После Test 3

- Финальное значение Z_PEN_DOWN (если правил скрипт) → записать в `runlog.md`, обновить в `scripts/svg_to_gcode.py`
- Если правил физически — отметить позицию ручки на корпусе модуля (ниткой / маркером)
- Перегенерить `output/notebook.gcode`:
  ```bash
  ./scripts/build.sh
  ```
- Скопировать на SD
- Переходить к Test 4 (одна страница в реальную тетрадь)

- Подогнуть левую часть тетради ВНИЗ под активную страницу (см. UMTS docs про толщину стопки)

→ Записать в runlog успешные параметры. После этого можно запускать полный прогон.

### 2.5. Ускорение: калибровочные листы (≈ 20 минут, один раз на держатель + ручку)

Страница пишется долго из-за **подъёмов пера**: P1S поднимает не голову, а весь стол, максимум 20 мм/с и 500 мм/с². Скорость рисования почти ни на что не влияет. Поэтому калибруются высота подъёма и режим пера, а не «скорость печати».

Все листы собираются одной командой на держатель (`--holder soft` для мягкого, `umts` для UMTS — **не путать**, разница по Z 33.5 мм). Отправлять как обычно: Orca → Device → Open G-code File. Каждый лист начинается с паузы установки держателя и заканчивается паузой снятия.

```bash
source .venv/bin/activate
python3 scripts/calibration_sheets_gcode.py zbench     --holder soft
python3 scripts/calibration_sheets_gcode.py hop-ladder --holder soft
python3 scripts/calibration_sheets_gcode.py speed      --holder soft --source build/9/gcode/page_01.gcode
python3 scripts/calibration_sheets_gcode.py page       --holder soft --gcode build/9/gcode/page_05.gcode
python3 scripts/calibration_sheets_gcode.py edge-check --holder soft --gcode-dir build/9/gcode
```

**0. Режим скорости на экране принтера.** Должен быть **Standard**. В Silent прошивка режет подачу до 0.7 и ускорение до 0.3 (данные реверс-инжиниринга X1Plus).

**1. `output/test_zbench.gcode` — ручка и бумага не нужны.** Только Z-движения на безопасной высоте. Каждый блок начинается одиночным сигналом и кончается двойным — засечь секундомером:
- блок A: 100 подъёмов × 3 мм, модель ≈ 37 с;
- блок B: 100 × 6 мм, модель ≈ 67 с;
- на паузе перед C переключить режим на **Ludicrous**, блок C: 100 × 3 мм. Если C заметно быстрее A — Ludicrous ускоряет Z, и для печати тетради его стоит включать. В конце вернуть Standard.

A и B против модели показывают, насколько реальный Z медленнее модели.

**2. `output/test_hop_ladder.gcode` — черновой лист на место тетради, ручка установлена.** 7 блоков, под каждым k засечек = номер блока. В блоке ручка многократно переезжает над только что нарисованными линиями с подъёмом:

| Засечек | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| Подъём, мм | 1.0 | 1.5 | 2.0 | 2.5 | 3.0 | 4.0 | 6.0 |

Найти блок с наименьшим подъёмом, где между короткими чёрточками **нет** протяжек и смазанных линий. Прибавить 0.5 мм запаса — это `PDF_TO_PRINT_Z_HOP_MM`. Если протяжки есть везде ниже 6 — ручка вставлена слишком глубоко (сильно сжата пружина), см. Test 3.

**3. `output/test_speed.gcode` — черновой лист.** Первая строка настоящего текста 5 раз, после копии k засечек:

| Засечек | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| мм/с | 50 | 100 | 150 | 250 | 500 |
| мм/с² | 3000 | 5000 | 8000 | 15000 | 20000 |

Выбрать самую быструю копию, неотличимую от первой (насыщенность, пропуски в начале штриха, дрожание мелких букв). По умолчанию стоит копия 2 (100 / 5000). На время страницы это влияет слабо (±1 мин).

**4. Пересобрать тетрадь с выбранными значениями:**
```bash
PDF_TO_PRINT_Z_HOP_MM=2.5 PDF_TO_PRINT_DRAW_SPEED_MM_S=100 PDF_TO_PRINT_DRAW_ACCEL_MM_S2=5000 \
  ./scripts/build_experimental.sh pdfs/9.pdf
```
`scripts/plot_time_sim.py build/9/gcode/page_*.gcode` показывает оценку по страницам.

**5. `output/test_page_05.gcode` — замер реального времени одной страницы** (в тетрадь или на черновик). Сравнить с `; est page time` в файле. Отношение реальное/модель → `PDF_TO_PRINT_TIME_FACTOR` (тогда остаток времени на экране станет честным). Записать в runlog.

### 2.6a. Печатный L-упор (`output/l_stop.stl`)

```bash
python3 scripts/l_stop_model.py            # output/l_stop.stl + output/l_stop_preview.png
```

- Плоская L-пластина **3 мм**, плечи 190×190 мм. Внутренние грани ровно на **24 мм от левого** и **50 мм от переднего края пластины** (те же `PAPER_LEFT` / `PAPER_FRONT`, из которых строится G-code).
- Снизу 6 карманов Ø10.3×2.1 мм под магниты **10×2 мм**: магниты держат упор на стальной пластине, упор не двигается при листании. Другие магниты: `--magnet-d 8 --magnet-h 3`.
- Скругление во внутреннем углу, чтобы угол тетради садился до упора.
- Печать: плашмя, нижней гранью на стол, PLA/PETG, масштаб 100 %. Магниты вдавить после печати.
- Установка: внешние кромки упора заподлицо с левым и передним краем пластины (сторона дверцы); тетрадь вдвинуть корешком и нижним краем в угол.

На модели (`printer_sim.py --l-stop-height 3`) держатель не касается упора: со сложенной тетрадью — при любом вылете ручки, с одиночным листом (spread) — при вылете ручки ниже корпуса держателя больше ~4 мм. Проверить вылет линейкой или листом `edge-check` без ручки.

### 2.6. L-упор можно не снимать — проверка за минуту

Держатель не может задеть упор, если упор **ниже нижней точки держателя в момент письма**. Нижняя точка находится над бумагой на величину вылета ручки из корпуса держателя (минус сжатие пружины). Ручка сама за край бумаги не выходит: самый близкий к краю текст — 1.4 мм от переднего края и ~5 мм от остальных (`pdfs/9.pdf`). Поэтому над передним краем корпус держателя проходит всегда.

- Упор **не выше тетради** (стопки под активной страницей) — столкновение невозможно в принципе.
- Упор выше тетради — нужен запас: (высота упора над бумагой) < (вылет ручки ниже корпуса − сжатие) − 1 мм.

Проверка без риска — `output/test_edge_check.gcode`:
1. Тетрадь и упор на месте, держатель установлен **без ручки** (корпус на той же высоте, что при письме).
2. Файл обводит прямоугольник крайних точек текста всех страниц на высоте письма со скоростью 20 мм/с.
3. Смотреть на держатель над упором. Если есть касание — Stop на экране и сделать упор ниже.
4. Прошёл — упор можно оставлять на весь прогон.

После смены PDF пересобрать `edge-check` (поля текста другие).

Без принтера то же проверяет симулятор (подставить свои замеры: вылет ручки ниже корпуса, толщину тетради, высоту упора):
```bash
python3 scripts/printer_sim.py output/9_experimental_fast.gcode --holder soft \
  --pen-protrusion 10 --paper-thickness 3 --l-stop-height 5
```
`PASS` — держатель не касается упора ни на одной странице; `STOP_COLLISION` — строка G-code и место касания.

## 4. Загрузка и печать

### Способ A — LAN-стрим (рекомендуется)

Самый надёжный путь. Orca отправляет gcode напрямую по сети, минуя SD-парсер прошивки.

1. Открыть Orca Slicer
2. Перейти на вкладку **Device** (с принтером, не Prepare/Preview!)
3. **Open G-code File** → выбрать `output/notebook.gcode`
   - ⚠️ НЕ через File → Open, НЕ через drag-and-drop в Plate, НЕ через Slice. Только Device → Open G-code File. См. §1.3.2.
4. Visual check в G-code preview: траектории видны, паузы стоят (~25 M0 пауз)
5. **Print** (или **Send to Printer**) → принтер запускает start G-code

### Способ B — SD-карта (fallback, может не работать)

⚠️ P1S firmware при чтении с SD строго валидирует gcode-формат (HEADER_BLOCK, THUMBNAIL, EXECUTABLE_BLOCK, CONFIG_BLOCK markers). Наш generated gcode эти блоки имеет (с версии после 2026-05-04), но прошивка может не принять без подписи Bambu Studio или специфичной структуры plate JSON.

Если LAN недоступен:
1. Скопировать `output/notebook.gcode` на SD карту
2. Вставить SD в P1S, выбрать файл на экране
3. Если прошивка отказывается / виснет / не показывает метаданные → перейти на LAN (способ A)

Если **SD обязательно**:
- Альтернатива: слайсить любой dummy-проект в Bambu Studio с правильным P1S-профилем, открыть результирующий gcode, скопировать целиком HEADER + THUMBNAIL + CONFIG блоки в наш generated gcode (вместо синтетических). Но это hacky workaround.
6. **Первая пауза «install module»**:
   - Открыть дверцу
   - Установить UMTS модуль с ручкой (см. UMTS docs §5)
   - Проверить: пружина свободна, не касается стекла, ручка вставлена правильно
   - Закрыть дверцу
   - На LCD/в Bambu Handy → Resume
7. Принтер рисует **страницу 1**
8. **Каждая следующая пауза «page flip»** (в G-code метка `;===== PAGE NN =====` — реальный номер страницы в PDF/тетради):
   - Принтер издаёт двухнотный chirp (C5→G5, ~0.5 сек) — сигнал паузы
   - Если подключён Bambu Handy app — приходит push-уведомление на телефон (включить: Handy → устройство → Уведомления → «Пауза печати» = ON)
   - Открыть дверцу
   - Перевернуть активную страницу тетради
   - Подогнуть левую часть ВНИЗ под активную (тетрадь не раскладываем плашмя — не помещается на стол)
   - Проверить выравнивание тетради по фиксатору / магнитам
   - Закрыть дверцу
   - Resume на LCD
9. **Последняя пауза перед концом** (после страницы 24, перед `bambu_end.gcode`):
   - Снять UMTS модуль (см. UMTS docs §6 — критично, не дать принтеру завершить с модулем)
   - На LCD → **Stop** (НЕ Resume — иначе выполнится end-блок: motors off, nozzle off; не страшно, но Stop надёжнее, чтобы исключить случайные движения)

### 4.1. Режим «распоротая тетрадь» (`spread`)

Если тетрадь **снята со скоб** и печатаете по **разворотам** (один физический сгиб = 4 страницы в плоскости), соберите G-code с порядком merge `spread`:

```bash
./scripts/build.sh pdfs/2.pdf output/notebook.gcode raster spread
# или
PDF_TO_PRINT_PAGE_ORDER=spread ./scripts/build.sh
```

**Отличие от обычного режима** (`sequential`, по умолчанию): тетрадь сложена, оператор листает 1 → 2 → … → 24. В режиме `spread` паузы идут в порядке **6 разворотов**, на каждом развороте подряд 4 страницы:

| Разворот | Порядок страниц |
|----------|-----------------|
| 1 (обложка) | 1 → 2 → 23 → 24 |
| 2 | 3 → 4 → 21 → 22 |
| 3 | 5 → 6 → 19 → 20 |
| 4 | 7 → 8 → 17 → 18 |
| 5 | 9 → 10 → 15 → 16 |
| 6 (середина) | 11 → 12 → 13 → 14 |

Полный разворот на столе по-прежнему может не помещаться — фиксируйте **активную** страницу как в §4; меняется только **последовательность** пауз под раскладку после снятия скоб. Только для **24-страничного** PDF.

**Таблица шагов и пауз:** [`spread-print-order.md`](spread-print-order.md).

## 5. Troubleshooting

### 5.0. «При запуске с SD-карты виснет / нет метаданных»

P1S firmware при чтении с SD требует строгий Bambu-формат gcode (HEADER_BLOCK + THUMBNAIL + EXECUTABLE_BLOCK + CONFIG_BLOCK + специфичную структуру). Наш generated gcode эти блоки имеет, но прошивка может всё равно отказать.

**Решение**: использовать **LAN-стрим** вместо SD. См. §4 Способ A.

LAN отправляет байты напрямую в принтер минуя SD-парсер. Работает надёжнее всего для нестандартного gcode (наш кейс — pen plotter без филамента).

Если SD обязательно — извлечь preamble из реально работающего Bambu Studio sliced gcode и подставить в наш файл вместо `metadata_header()` / `end_marker()` функций в `scripts/merge_pages.py`. Hacky, требует ручной работы.

### 5.1. «Принтер виснет, экран не реагирует, плита прогрелась»

С версии после 2026-05-04 start G-code **переписан в minimal-вариант** именно из-за этих проблем. Удалены команды которые валили P1S firmware:

- ❌ Удалено: `G29 A...` (ABL bed leveling) — firmware автоматически грел плиту до ~50°C ДО прозондирования (thermal expansion compensation), и часто таймаутил без филамента
- ❌ Удалено: `M970.3 / M974` (mech mode fast check, виброкалибровка) — фейлится без филамента, может зависнуть
- ❌ Удалено: `M976` (heatbed scan) — не нужен
- ❌ Удалено: wipe nozzle sequence — нужна для прайминга филамента, без филамента может крашить firmware
- ✅ Добавлено: `M140 S0` явно в начале (плита холодная, без auto-heat)

**Pause command**: `M400 U1` (Bambu interactive pause) — единственный работающий pause-командой на P1S. `M0` / `M601` / `M226` Bambu firmware игнорирует.

Минимальный start gcode теперь делает только:
1. Reset state, fans off, soft endstops off
2. M140 S0 — плита холодная
3. G28 home → Z=20 raise
4. Heat nozzle to 180°C (cold extrusion prevention)
5. Park + M0 pause для install модуля

Если **до сих пор виснет** при minimal start gcode — проблема глубже:
- Смотри что выводит экран P1S перед зависанием (последнее сообщение)
- Проверь что в `output/notebook.gcode` действительно minimal-версия:
  ```bash
  grep -c "G29 A" output/notebook.gcode    # должно быть 0
  grep -c "M970.3" output/notebook.gcode   # должно быть 0
  grep -c "M0$" output/notebook.gcode      # ~25 (1 install + 23 flip + 1 end)
  grep -c "M400 U1" output/notebook.gcode  # должно быть 0
  ```
- Если есть G29 / M970.3 — у тебя устарелый файл, перегенерируй `./scripts/build.sh`
- Если файл свежий и все равно виснет — попробуй еще более минимальный gcode (только G28 home + M0):
  ```gcode
  G90
  G28
  G1 Z20 F600
  M0
  ```
  И проверить — встаёт ли в паузу. Если да — проблема в одной из оставшихся команд (M104/M109 heat, M221 soft endstop). Если нет — проблема в подключении / firmware / отправке файла

### 5.2. «В предпросмотре нет времени печати»

С версии после 2026-05-04 в gcode добавлены `M73`, `;LAYER:N`, header-блок. Проверь:

```bash
head -10 output/notebook.gcode    # должно начинаться с "; HEADER_BLOCK_START"
grep -c "^;LAYER:" output/notebook.gcode    # ожидаем 47 (24 страницы + 23 паузы)
grep -c "^M73 " output/notebook.gcode    # ожидаем 49
```

Если этих маркеров нет → ты используешь старую версию gcode, перегенерируй:
```bash
./scripts/build.sh
```

Время в предпросмотре — **модель планировщика** по каждой странице (`scripts/plot_time_sim.py`). Реальное время одной страницы записать в runlog и задать поправку:
```bash
PDF_TO_PRINT_TIME_FACTOR=1.3 ./scripts/build_experimental.sh pdfs/9.pdf   # реальное / модель
```
Плоская оценка по-старому: `python3 scripts/merge_pages.py --minutes-per-page 20`.

### 5.3. Прочее

| Симптом | Причина / решение |
|---|---|
| `M400 U1` пауза не срабатывает (принтер просто продолжает) | См. §5.1 — fallback на `M0` |
| Линии бледные или нет рисунка | Z-offset слишком большой → уменьшить (например 18 → 17.5) или вставить ручку глубже |
| Давит сильно, чернила размазаны | Z-offset слишком мал → увеличить (например 18.7 → 19.0) или вытащить ручку |
| Ручка тащит чернила во время travel | Z-hop не работает → проверить `Retraction = 0.01 мм` в Orca, `Z-hop = 3 мм Normal` |
| Тетрадь сдвинулась после паузы | Слабая фиксация → больше магнитов, проверить плоскость магнитного листа, не открывать дверцу резко |
| Игнорирует тонкие линии | В Orca включить Arachne, `Wall min ≈ 0.2 мм` |
| Большой G-code (~150 МБ), Orca тормозит | Печатать через прямой LAN-стрим (Device → Send to Printer), не через симуляцию слайсера |
| Превышает excluded area (X<48 или Y<55 в pen-frame после трансформа) | Смотри `scripts/svg_to_gcode.py`, увеличь PAPER_ORIGIN_X (но не больше 24+30=54) или PAPER_ORIGIN_Y |
| Нечётные / чётные страницы должны чередоваться | См. §3, нужна правка скрипта (TBD) |

```bash
# Полный pipeline (сложенная тетрадь, PDF-порядок)
./scripts/build.sh

import re; from pathlib import Path
for p in sorted(Path('build/gcode').glob('page_*.gcode')):
    xs, ys = [], []
    for line in p.open():

        if m: xs.append(float(m[1])); ys.append(float(m[2]))
    print(f'{p.name}: X={min(xs):.1f}..{max(xs):.1f} Y={min(ys):.1f}..{max(ys):.1f}')
"

# Подсчёт пауз в финальном файле
```
